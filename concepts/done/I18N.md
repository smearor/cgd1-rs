# I18N — Internationalization of cgd1-rs-controller

## Motivation

The `cgd1-rs-controller` GTK 4 desktop application currently contains all
user-facing strings hardcoded in English.  To make the application accessible
to a broader audience — in particular German-speaking users who are already
the primary target group (fallback language in `dice-rs/games/yahtzee` is
`de`) — the UI should be internationalized.

The chosen approach follows the proven i18n implementation from the
`dice-rs/games/yahtzee` project, which uses the **Fluent** localization
ecosystem:

- `fluent-bundle` — Fluent resource model
- `i18n-embed` — runtime locale detection and embedding
- `i18n-embed-fl` — compile-time-checked `fl!` macro for translation lookup
- `rust-embed` — embeds `.ftl` files into the binary at compile time
- `unic-langid` — language identifier parsing

## Approach

### Fluent + rust-embed + i18n-embed

| Aspect | Choice |
|---|---|
| Localization system | Fluent (`.ftl` files) |
| Embedding | `rust-embed` (compile-time embedding of `i18n/` directory) |
| Runtime locale detection | `i18n-embed::DesktopLanguageRequester` |
| Fallback language | `en` (English — all source strings are currently English) |
| Translation lookup | `fl!` macro (compile-time message-ID validation) |
| Dynamic lookup | `get()`, `get_int()`, `get_str()` helper functions |

### Why Fluent over gettext?

- Fluent supports **gender, pluralization, and nested arguments** natively.
- `.ftl` files are simple key-value text files, easy for translators.
- Compile-time checking via `i18n-embed-fl::fl!` catches missing message IDs
  at build time.
- Already proven in `dice-rs/games/yahtzee` — same ecosystem, same patterns.

### `cgd1-rs-controller/src/i18n.rs`

Core i18n module, modeled after `yahtzee/src/i18n.rs`:

```rust
//! Internationalization support using the Fluent ecosystem.

use std::sync::OnceLock;

use i18n_embed::DesktopLanguageRequester;
use i18n_embed::fluent::FluentLanguageLoader;
use i18n_embed::fluent::fluent_language_loader;
use rust_embed::RustEmbed;

/// Embeds the `i18n/` directory containing `.ftl` files into the binary.
#[derive(RustEmbed)]
#[folder = "i18n/"]
struct Localizations;

/// The global fluent language loader.
static LOADER: OnceLock<FluentLanguageLoader> = OnceLock::new();

/// Get the global language loader, initializing it on first access.
pub fn loader() -> &'static FluentLanguageLoader {
    LOADER.get_or_init(|| {
        let loader = fluent_language_loader!();

        let requested = DesktopLanguageRequester::requested_languages();
        let languages = i18n_embed::select(&loader, &Localizations, &requested);

        if let Err(error) = languages {
            tracing::warn!(error = %error, "failed to load requested languages, falling back to default");
        }

        loader
    })
}

/// Convenience macro wrapping `i18n_embed_fl::fl!` with the static loader.
#[macro_export]
macro_rules! fl {
    ($message_id:literal) => {{
        i18n_embed_fl::fl!($crate::i18n::loader(), $message_id)
    }};

    ($message_id:literal, $($args:expr),*) => {{
        i18n_embed_fl::fl!($crate::i18n::loader(), $message_id, $($args), *)
    }};
}

/// Get a translated message by ID without compile-time checks.
pub fn get(message_id: &str) -> String {
    loader().get(message_id)
}

/// Get a translated message with a single string argument.
pub fn get_str(message_id: &str, arg_name: &str, value: &str) -> String {
    let mut args = fluent_bundle::FluentArgs::with_capacity(1);
    args.set(arg_name, value);
    loader().get_args_fluent(message_id, Some(&args))
}

/// Get a translated message with a single integer argument.
pub fn get_int(message_id: &str, arg_name: &str, value: i64) -> String {
    let mut args = fluent_bundle::FluentArgs::with_capacity(1);
    args.set(arg_name, value);
    loader().get_args_fluent(message_id, Some(&args))
}

/// Initialize the i18n system.
pub fn init() {
    let _ = loader();
}
```

## Replacement Patterns

### Static string → `fl!` macro

Before:
```rust
let status_label = Label::builder().label("Disconnected").build();
```

After:
```rust
let status_label = Label::builder().label(&fl!("status-disconnected")).build();
```

### `format!` with args → `fl!` with args

Before:
```rust
status.set_label(&format!("Connected to {addr}"));
```

After:
```rust
status.set_label(&fl!("status-connected", addr = addr.to_string()));
```

### Dynamic lookup (runtime key) → `get()` / `get_str()`

Before:
```rust
let day_name = weekday_short(when.weekday());
```

After:
```rust
let day_name = i18n::get(weekday_fluent_key(when.weekday()));
```

Where `weekday_fluent_key` maps `Weekday::Mon` → `"weekday-mon"`, etc.

### Tooltip text

Before:
```rust
let scan_button = Button::builder().tooltip_text("Scan for devices").build();
```

After:
```rust
let scan_button = Button::builder().tooltip_text(&fl!("tooltip-scan")).build();
```

## Implementation Procedure

### Phase 1: Infrastructure

1. Add i18n dependencies to workspace `Cargo.toml` and `cgd1-rs-controller/Cargo.toml`.
2. Create `cgd1-rs-controller/i18n.toml`.
3. Create `cgd1-rs-controller/src/i18n.rs` (modeled after `yahtzee/src/i18n.rs`).
4. Create `cgd1-rs-controller/i18n/en/cgd1.ftl` with all English keys.
5. Create `cgd1-rs-controller/i18n/de/cgd1.ftl` with all German translations.
6. Add `mod i18n;` to `src/main.rs` and call `i18n::init()` before app startup.
7. Verify the build compiles with the `fl!` macro resolving against the `.ftl` files.

### Phase 2: Replace Hardcoded Strings

Work through each file in order, replacing hardcoded strings with `fl!` calls:

1. `src/window.rs` — window title, toggle labels, tooltips, status messages, menu items.
2. `src/app.rs` — message dialog strings.
3. `src/dialog/info.rs` — info dialog strings.
4. `src/dialog/alarm_editor.rs` — buttons, tooltips, day labels, status messages.
5. `src/dialog/display_editor.rs` — frame titles, row labels, tooltips, buttons, status messages.
6. `src/dialog/region_editor.rs` — frame title, row labels, toggle labels, buttons, tooltips, info label, status messages.
7. `src/dialog/sensor_overview_editor.rs` — refresh button, column titles.
8. `src/dialog/audio.rs` — frame titles, row labels, buttons, tooltips, info labels, file chooser, status messages.
9. `src/next_alarm.rs` — weekday short names.
10. `src/config/time_based_blink.rs` — `"Off"` label.

### Phase 3: Testing

1. Run the application with `LANG=en` to verify English fallback.
2. Run the application with `LANG=de` to verify German translations.
3. Run with an unsupported locale (e.g. `LANG=fr`) to verify fallback to English.
4. Verify all `fl!` macro calls compile (compile-time check ensures no missing keys).
5. Run `cargo clippy` and `cargo fmt` to ensure code quality.

### Phase 4: Documentation

1. Update `README.md` with a note about i18n support.
2. Document how to add a new language: create `i18n/{lang}/cgd1.ftl`, add language to `i18n.toml` if needed.
3. Document the `fl!` macro usage pattern for contributors.

## Notes

- **Fallback language is `en`** (not `de` as in yahtzee), because all source strings are currently English.
- **Timezone labels in `common.rs`** are kept in English for now — they are technical identifiers.
- **Ringtone names** (from `RingtoneSignature::name()`) are device firmware identifiers and not translated.
- **Log messages** (`tracing::debug!`, `warn!`, `info!`, `error!`) are developer-facing and not translated.
- **CLI help text** in `main.rs` (`#[command(about = ...)]`, `#[arg(help = ...)]`) could be translated in a future phase using `clap`'s i18n support, but is low priority.
- **Sensor unit strings** (`°C`, `%`) are universal and do not need translation.
- The `fl!` macro provides **compile-time validation** of message IDs — if a key is missing from the `.ftl` file, the build will fail.  This ensures no missing translations slip through.
